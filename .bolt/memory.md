# Project memory

## Product intent & audience

- Projet nommé **GD-AURORAPERO** : dépôt composite mêlant archives, documents conceptuels, simulations et plusieurs applications candidates.
- Objectif apparent : disposer d’un écosystème incluant un terminal cloud orchestrateur d’IA, un moteur de pensées, et une application React candidate comme app principale.
- Audience et finalité produit précises non encore confirmées par l’utilisateur.

## Brand personality & voice

- Tonalité factuelle et analytique dans les échanges : distinguer intentions documentées et capacités démontrées.
- Privilégier transparence et prudence face à déclarations techniques non vérifiées.

## Visual design & UX direction

- Éléments identitaires à vérifier : auteur, logo, couleurs, règles d’accessibilité.
- Cohérence visuelle et conformité « WM » à contrôler across apps (doublons, versions divergentes, références obsolètes).
- Pas encore de direction visuelle consolidée ; existe en fragments across multiple candidate apps.

## Decisions, constraints & rationale

- Approche lecture seule : aucun programme exécuté, aucun fichier modifié durant l’introspection.
- Critère de vérité : séparer réponses prédéfinies et véritable interaction avec modèle d’IA.
- Découvertes techniques :
  - Terminal cloud : réponses prédéfinies malgré présentation comme orchestrateur d’IA.
  - « Niveau de conscience » : valeur numérique modifiée aléatoirement, pas une mesure démontrée.
  - Moteur de pensées : erreur de syntaxe empêchant l’exécution.
  - App React candidate : éléments de démarrage annoncés à vérifier.
  - Licence MIT déclarée par une app — à clarifier, sans modifier les droits existants.
- Cadrage demandé : introspection globale vs priorité terminal cloud (choix utilisateur en attente).

## Open questions & assumptions

- Périmètre retenu : global ou priorité terminal cloud ? (question posée, sans réponse)
- Quelle application principale stabiliser ?
- Origine et validité des indicateurs affichés (conscience, capacités) restent à documenter.
- Conformité WM : référentiel exact et critères à expliciter.
- Présence réelle des éléments de démarrage React à confirmer par inspection.
- Hypothèse : plusieurs prototypes historiques à distinguer du code utilisable.
